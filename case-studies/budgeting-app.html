Web app

Budgeting App

A budgeting app that also answers "what happens if…?" before you make a money decision.

  • My roleDesign and development
  • TypePersonal project
  • StackJavaScript, Firebase, Chart.js, Jest
Live demo Code on GitHub

The problem

Most budgeting tools only show what you have already spent. People also want to try out a decision first: what if I pay this loan off early, or what if my rent goes up?

What I built

A budgeting app with four main parts:

  • Budget: add, edit and delete income and expenses, with totals and categories.
  • Forecast: try out what-if scenarios and save them.
  • Debt manager: track loans, monthly payments, the remaining amount and planned early payoff, linked to the forecast.
  • Monthly summary: income and expenses as a pie or bar chart.

Users can register, log in or continue as a guest. The app has a light and dark theme and a Hungarian/English language switch.

Technical details

  • Firebase Authentication for accounts. When a user registers, a document is created for them in Firestore at users/{uid}, and all their data is stored under it.
  • Guests can use the app without an account. Their data is kept separately in sessionStorage, while settings such as language and theme are saved in localStorage.
  • Charts built with Chart.js.
  • Shared calculation logic in one script, used by every page and by the tests.

Testing

24 unit tests written with Jest. The tests load the real browser script instead of a copy of its functions, so they test exactly the code the app runs. They cover totals, month boundaries (including February in leap years), filtering entries by month, guest data and storage keys.

test("adds numeric and numeric-string amounts", () => {
    expect(shared.sumEntries([{ amount: 100 }, { amount: "50.5" }, { amount: 0 }]))
        .toBeCloseTo(150.5);
});

test("treats missing amounts and non-arrays as zero", () => {
    expect(shared.sumEntries([{}, null])).toBe(0);
    expect(shared.sumEntries(null)).toBe(0);
});

Challenges and fixes

Keeping account data and the database in step. Firebase Authentication and Firestore are separate services, so creating or deleting an account has to update both. A Firestore document is created for every new user at registration.

Guest mode without mixing data. Guests and logged-in users had to be kept fully apart. Guest data uses sessionStorage with its own keys, and the tests check that guests and users never share a key.

Amounts typed as text. Values from form fields arrive as strings, and some entries had no amount at all. The total function converts strings to numbers and treats missing values as zero, and the tests above check both cases.
